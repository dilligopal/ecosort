# 🌿 EcoSort – Waste Classification Using Image Recognition

> **ECE 5th Semester Academic Computer Vision Project**
> Department of Electronics and Communication Engineering

---

## 📌 Project Overview

**EcoSort** is a full-stack AI web application that uses a pretrained **MobileNetV2** deep learning model, fine-tuned on a real waste image dataset, to classify waste from photos into six actionable categories with tailored disposal guidance.

Users can upload an image file or capture a live camera snapshot. The image pixels are sent to a Flask backend where genuine neural inference produces:
- A predicted waste category
- A softmax confidence score
- Sustainable disposal recommendations

> **Academic Honesty Notice:** All predictions come from genuine pixel-level model inference. No filename-based rules, randomness, or fake confidence values are used.

## 🤖 Training the AI Model

### Step 4 – Download the waste dataset

```bash
python train.py --download
```

This downloads the **Garbage Classification dataset** (~220 MB, ~12,000 images) and remaps the 12 original class folders into the 8 EcoSort training labels.

If automatic download fails, download manually:
1. Go to https://www.kaggle.com/datasets/asdasdasasdas/garbage-classification
2. Download the ZIP file
3. Place `garbage_classification.zip` in the project root
4. Run `python train.py --download` again

### Step 5 – Train the model

```bash
python train.py --epochs 15 --batch-size 32
```

**Training phases:**
- **Phase 1 (5 epochs):** Backbone frozen → only the classification head trains. Fast convergence.
- **Phase 2 (10 epochs):** Full network fine-tuned with a lower learning rate.

The best validation checkpoint is saved automatically to `models/ecosort_mobilenetv2.pth`.

**Estimated training time (CPU):**

| Hardware | Approximate Time |
|---------|-----------------|
| Modern laptop CPU (Core i5/i7) | 45–90 minutes |
| Older CPU | 2–4 hours |
| GPU (CUDA) | 5–15 minutes |

**Expected validation accuracy:** ~85–92% on the garbage classification dataset.

To use a smaller batch size if you run out of memory:
```bash
python train.py --epochs 15 --batch-size 16
```

Returns the EcoSort HTML application.

### `GET /health`
Returns service and model status.

**Response 200:**
```json
{
  "status": "ok",
  "service": "EcoSort Waste Classification API",
  "model_ready": true,
  "model_path": "models/ecosort_mobilenetv2.pth",
```

### `POST /predict`

**Request:** `multipart/form-data` with field `image` (JPEG / PNG / WEBP, max 5 MB)

**Success Response 200:**
```json
{
  "success": true,
  "category": "Glass",
  "confidence": 0.8721,
  "confidence_percent": 87.2,
  "uncertain": false,
  "disposal_guidance": ["...", "..."]
}
```

**Error Responses:**

| Status | Meaning |
|--------|---------|
| 400 | Missing file or empty filename |
| 413 | File exceeds 5 MB limit |
| 415 | Unsupported image format |
| 422 | Corrupt or unreadable image |
| 503 | Model not loaded (run train.py) |
| 500 | Internal inference error |

## ☁️ Render Deployment

### One-time setup

1. **Train and test locally** until the app works on your machine.

2. **Upload the trained model to Google Drive:**
   - Go to Google Drive → upload `models/ecosort_mobilenetv2.pth`
   - Right-click → **Share** → **Anyone with the link** → **Viewer**
   - Copy the File ID from the URL: `https://drive.google.com/file/d/FILE_ID_HERE/view`

3. **Push code to GitHub** (see section above).

### Deploy on Render

1. Go to https://render.com and sign in
2. Click **New** → **Web Service**
3. Connect your GitHub repository
4. Render detects `render.yaml` automatically
5. Set **Environment Variables** in the Render dashboard:
   ```
   GDRIVE_MODEL_FILE_ID = <your_google_drive_file_id>
   FLASK_DEBUG = 0
   FLASK_ENV = production
   ```
6. Click **Create Web Service**

Render will:
- Install Python dependencies
- Run `download_model.py` to fetch model weights from Google Drive
- Start Gunicorn on the assigned port
- Health-check `/health` every 30 seconds

Your live URL will be: `https://ecosort.onrender.com` (or similar)

## ❗ Common Errors & Solutions

### `ModuleNotFoundError: No module named 'flask'`
**Cause:** Virtual environment not activated.
**Fix:**
```bash
# Windows
venv\Scripts\activate

# macOS/Linux
source venv/bin/activate

pip install -r requirements.txt
```

### `RuntimeError: Model is not loaded.`
**Cause:** `models/ecosort_mobilenetv2.pth` not found.
**Fix:** Train the model first:
```bash
python train.py --download --epochs 15
```

### `Camera error: NotAllowedError`
**Cause:** Browser denied camera permission.
**Fix:** Click the camera icon in the browser address bar and allow access. Camera requires HTTPS or localhost.

### `File size exceeds 5 MB limit`
**Cause:** Image too large.
**Fix:** Compress the image or use a smaller file.

### Training `KeyError` / class mismatch
**Cause:** Dataset folder names differ from expected.
**Fix:** Check `dataset/` contains folders named exactly: `Cardboard`, `Electronic Waste`, `Glass`, `Metal`, `Organic Waste`, `Paper`, `Plastic`, `Trash`.

### Render deployment: `model_ready: false`
**Cause:** `GDRIVE_MODEL_FILE_ID` not set or download failed.
**Fix:** Verify the Google Drive share link is public and the file ID is correct in Render environment variables.

## 🔬 Model Details & Limitations

### Architecture
- **Model:** MobileNetV2 (pretrained on ImageNet-1K)
- **Fine-tuning:** Two-phase strategy – warm-up (head only) then full network
- **Input:** 224×224 RGB, ImageNet normalisation
- **Output:** 8-class softmax
- **Framework:** PyTorch 2.3 (CPU-compatible)
- **Model size:** ~14 MB (`.pth` file)

### Dataset
- **Source:** [Garbage Classification – Kaggle](https://www.kaggle.com/datasets/asdasdasasdas/garbage-classification)
- **License:** Please verify dataset licence on the Kaggle page before redistribution
- **Images:** ~12,000 across 12 original classes (merged into 8 EcoSort labels)

### Known Limitations
- **Multi-object images:** Model trained on single-item images; cluttered scenes reduce accuracy
- **Lighting sensitivity:** Very dark or overexposed images may classify incorrectly
- **Composite materials:** Items made of multiple materials (e.g. Tetra Pak) may be uncertain
- **Clothes / shoes:** Mapped to "Unknown / Uncertain" as they are domain-specific waste
- **Accuracy:** Self-reported validation accuracy on held-out split. Real-world accuracy depends on image quality and waste type distribution
